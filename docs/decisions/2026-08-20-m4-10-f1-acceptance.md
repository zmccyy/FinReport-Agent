## 关键决策

### D1. Ground truth 全量化重建（moutai_2025.json 17 项 → 125 行）

M2.12 的 GT 是 regex 抽样的 17 项关键科目（README 自述需人工核对），且
regex 抓错值（营业利润 1000.008、固定资产 155949——后者实为现金流量表
「处置固定资产收回现金」行）。稀疏 GT 下 F1 被抽取全量行拖死（FP 爆炸），
regex 错值让真实 API 永远匹配不上。

**决定**：`scripts/rebuild_moutai_gt.py` 从 PDF 文本层（PyMuPDF 词级坐标）
重建全量 GT——按 y 聚类行、x 分列（科目/附注号/本期/上期），值行与重叠
科目行配对解决跨行单元格；「合并/母公司」标题切段只取合并。产出
BS 53 / IS 38 / CF 34 行（合并+本期），平衡关系逐项平账
（资产=负债+权益、流入-流出=净额）。原 GT 备份 `moutai_2025.m2sample.json.bak`。

### D2. select_table 报表标题段定位（替代单表评分）

旧逻辑按「表内关键词命中数」选单表：合并利润表跨 61/62 页拆散后各页
命中 2 词，母公司整页表命中 4 词胜出 → 抽到母公司报表（scope 标合并）。
且表内无「母公司」字样（标题在表格外），旧降权失效。

**决定**：按页文本「合并XXX表」标题定位段起点、「母公司XXX表」标题定位
终点；段内命中页的表**整页并入**（y 坐标切分混合页：61 页权益尾 vs 利润表、
59 页合并尾 vs 母公司头）；无表页（64 页 PP-DocLayout 漏检的合并现金流
头部）用行文本降级重建 HTML。scope 由段锚定恒为「合并」，prompt 显式注入。

### D3. max_tokens 8192 → 16384、超时 60s → 300s

deepseek-v4-flash（reasoning 模型）把 token 预算先花在 reasoning_content，
跨页拼接 HTML（~5KB）+ 全量 JSON 输出下 content 直接为空
（finish_reason=length）——真实 E2E 首轮全链路「success 但三表为空」。
16384 + 300s 实测 IS 77 行（合并×本期/上期）抽取成功。

### D4. 科目名规范化（与 GT 同一套规则）

LLM 原样保留表格行号（一、营业收入）、行性质前缀（减：营业成本）、
括号注释（（损失以…号填列））、识别空格（现 金）。抽取结果落库前
`normalize_item_name()` 清洗（去行号/前缀/括号注释/全角符号/空格），
eval 匹配前对预测侧同规则规范化（GT 侧幂等）。

### D5. MQ 双线程消费者（M4.10 修复，与 F1 复测同批）

parse 单条 handler 可阻塞 >7min，I/O 线程同步执行时 30s heartbeat 停发
→ broker 断连 → ack 丢失 → 消息无限重投。拆为 I/O 线程（收包/心跳/ack）
+ 工作线程（handler），ack 经 `add_callback_threadsafe` 回调度。
5 个旧 task_consumer 测试同步适配（`_run_queued_delivery` 内联 drain）。

### D6. 已知边界（非阻塞，留 M5）

- **57 页表格识别缺行**：PP 的 HTML 里无「货币资金」等行（单元格合并问题），
  LLM 无从抽取 → BS FN 4 项、FP 1 项
- **64 页合并现金流头部**：表格识别漏检页，文本降级重建后 LLM 未完整写入
  （CF FN 7 项中 5 项在经营段）——EXTRACT 经历过 RETRY/PARTIAL
- **每股收益表外行**：LLM 抽取了利润表页脚的每股收益（65.66 元/股），
  GT 已过滤，FP 2 项
- **e2e/评估脚本依赖宿主机 requests**；eval 输出 stdout 缓冲（无实时进度）
- **prod 镜像体积复测未执行**（本机 Debian CDN 502，M4.09 已知）
